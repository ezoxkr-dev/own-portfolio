Boundary-Aware Semantic Chunking (src/lib/chunk.ts)

Instead of naive fixed-character truncation that cuts sentences in half, the chunker uses a sliding character window of target size 1,200 characters with 150-character overlap. Inside the tail 45% of the window, it locates the nearest semantic boundary (\n\n, . , ! , ? ) so chunks remain coherent paragraphs.

const CHUNK_TARGET = 1200;
const CHUNK_OVERLAP = 150;
// Breaks preferentially at paragraph and sentence delimiters
Google Gemini Embeddings (src/lib/embed.ts)

Leverages gemini-embedding-001 via direct REST calls to POST /v1beta/models/gemini-embedding-001:batchEmbedContents. Documents are embedded with task type RETRIEVAL_DOCUMENT in batches of up to 16, while user search queries are embedded with RETRIEVAL_QUERY to optimize vector space alignment. Includes automated retry with exponential backoff and jitter for handling 429/503 spikes.

Grounding & Zero-Hallucination Guardrails (src/lib/answer.ts)

The generation engine is powered by gemini-3.8-flash. Context is formatted into numbered passages ([1] Source: filename\n{content}) up to 24,000 characters.

  • Strict Citation Requirement: Must cite supporting passage numbers like [1] or [2][3] for each factual statement.
  • Defensive Fallback: If the context lacks the answer, the model responds: "I do not have that information in the knowledgebase yet." No fabricated figures or outside facts.
  • Zero Thinking Latency: Uses thinkingConfig: { thinkingBudget: 0 } to prevent long reasoning chains, dropping latency into the sub-2-second range.
  • Bilingual Language Mirroring: Automatically synthesizes the answer in Bengali or English based on the input question language.
Non-Blocking Ingestion & Persistent State Machine

Uploading files (PDF/DOCX) can take time to embed. Rather than blocking the user's browser, the system uses Vercel Fluid Compute's waitUntil primitive:

  1. On upload, text is extracted synchronously and saved to PostgreSQL as pending chunk rows; HTTP 200 is returned immediately.
  2. Embedding generation continues in the serverless worker after the response is sent.
  3. All job states live in PostgreSQL (pending → processing → completed / failed), never ephemeral memory.
  4. Resumption Mechanism: If a job is aborted, every admin dashboard load hits /api/jobs/resume to reclaim stale pending chunks, plus an hourly Vercel Cron sweep (/api/cron/process) guarantees 100% completion.
Speech-to-Text with Groq Whisper (src/lib/transcribe.ts)

The visitor interface integrates live microphone recording via the browser's MediaRecorder API (WebM/Opus). The audio payload is streamed to /api/transcribe, which invokes the Groq Whisper API (whisper-large-v3) at temperature=0.

This delivers sub-second, highly accurate multilingual transcription for both English and conversational Bengali campus queries before querying the vector database.

pgvector Production Schema (scripts/init-db.mjs) 
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE projects (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE documents (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  filename text NOT NULL,
  mime_type text NOT NULL,
  size_bytes bigint NOT NULL,
  chunk_count integer NOT NULL DEFAULT 0,
  status text NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'processing', 'completed', 'failed')),
  error text,
  created_at timestamptz DEFAULT now()
);

CREATE TABLE chunks (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id uuid NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  project_id uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  seq integer NOT NULL,
  content text NOT NULL,
  status text NOT NULL DEFAULT 'pending',
  attempts integer NOT NULL DEFAULT 0,
  embedding vector(3072),
  UNIQUE (document_id, seq)
);

-- Cosine Nearest Neighbor Retrieval:
SELECT id, filename, content, 
       1 - (embedding <=> $query_vec) AS similarity
FROM chunks JOIN documents ON chunks.document_id = documents.id
WHERE 1 - (embedding <=> $query_vec) >= 0.55
ORDER BY embedding <=> $query_vec
LIMIT 8;
